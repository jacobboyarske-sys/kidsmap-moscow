# KidsMap Moscow

Учебный pet-проект: карта детских событий Москвы на Streamlit с фильтрами по дате,
категории и возрасту, классификацией событий (правила + ML) и сбором данных с сайтов
афиш. Подробный пошаговый план — в [tutorials/README.md](tutorials/README.md); каждый
этап оформлен отдельным нумерованным файлом `tutorials/туториал_N.md`.

## Главное правило работы над этим проектом

Это учебный проект: **код пишет пользователь, а не Claude Code за неё**. Цель —
восстановить навыки Python/Streamlit/ML после перерыва, а не получить готовое
приложение как можно быстрее. Из этого следует:

- Не пиши сразу целые модули/файлы за один запрос без обсуждения — предлагай план,
  дай пользователю написать код самостоятельно, помогай точечно (объяснение,
  ревью, подсказка по конкретной функции).
- Для новых крупных шагов (новый этап туториала) сначала предложи план и обсуди его,
  прежде чем писать код.
- Если пользователь просит написать код целиком — это нормально, но по умолчанию
  предпочитай режим "подсказчика и ревьюера", а не "автора".
- Объясняй *почему*, а не только *что* — особенно для ML-решений (почему эта модель/
  метрика/подход, а не другой).

## Стек

- Python 3.11+, venv
- Streamlit + pydeck — интерфейс и карта
- pandas, pydantic — данные и валидация
- scikit-learn — классификация категорий (TF-IDF + LogisticRegression)
- requests + BeautifulSoup4 — скрапинг афиш (этап 5)

## Структура проекта (целевая, наполняется по этапам)

```
tutorials/TUTORIAL.md      # пошаговый план проекта
data/seed_events.json      # вручную собранные события
data/events.json           # рабочий датасет (seed + спарсенное)
src/models.py               # pydantic-модель Event
src/app.py                  # Streamlit-приложение
src/classify.py              # правила (возраст) + ML (категория)
src/train_classifier.py      # обучение модели категорий
src/scrapers/                # по одному модулю на сайт-источник
tests/
```

## Соглашения

- Код и идентификаторы — на английском, комментарии/докстринги — по ситуации, но
  общение с пользователем в чате — на русском.
- Маленькие, атомарные изменения; коммит после каждого законченного шага/этапа.
- Перед коммитом — пользователь сам просматривает diff.
- Данные о событиях всегда проходят через pydantic-модель `Event`, "сырых" dict
  в рабочем коде быть не должно.
