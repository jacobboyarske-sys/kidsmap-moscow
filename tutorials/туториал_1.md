# Туториал 1. Окружение и первое знакомство с Claude Code

(~30-60 мин)

Этот этап — база для всего остального: изолированное окружение, список
зависимостей и первый коммит. Ничего специфичного для карты/ML тут ещё нет, зато
все команды из этого раздела вы будете использовать в каждой будущей сессии.

Все команды ниже — для терминала **PowerShell внутри VS Code** (не Git Bash). Чтобы
его открыть: `Ctrl + ~` (тильда) или меню *Terminal → New Terminal*. Важно, чтобы
терминал был открыт именно в папке проекта (`inspo_project`) — в VS Code это обычно
так по умолчанию, проверить можно командой `pwd` (покажет текущий путь).

## Шаг 1. Зачем нужно виртуальное окружение (venv)

На компьютере уже стоит несколько версий Python (можно проверить: у вас, например,
их минимум три — 3.11, 3.9 и версия из MSYS2). Если ставить библиотеки
(`pip install streamlit`) глобально, они уйдут в одну из этих системных версий и
будут:
- доступны *всем* Python-проектам на компьютере одновременно, включая несовместимые
  друг с другом версии библиотек для разных проектов;
- не переносимы — если через месяц вы захотите показать проект на другом компьютере
  или ноутбуке, придётся вручную вспоминать, что и в какой версии было установлено.

**Виртуальное окружение (venv)** — это папка внутри проекта со своей отдельной,
изолированной копией Python и `pip`. Всё, что вы ставите, пока это окружение
активно, остаётся только в этой папке и не трогает ни системный Python, ни другие
проекты. Стандартная практика — одно окружение на проект.

## Шаг 2. Проверить Python

```powershell
python --version
```

Должно показать `Python 3.11.1` (или близкую версию 3.11.x) — это нормально, дальше
используем именно эту команду. Если бы показалась версия 3.9 или что-то от MSYS2 —
это был бы повод разобраться с `PATH`, но у вас `python` уже резолвится в 3.11.1,
так что можно идти дальше.

## Шаг 3. Создать виртуальное окружение

Находясь в корне проекта (`inspo_project`):

```powershell
python -m venv .venv
```

Разбор команды: `python -m venv` — запустить встроенный в Python модуль `venv`,
`.venv` — имя папки, которую он создаст (точка в начале — просто соглашение,
означает "служебная/скрытая папка"). Выполнится один раз, появится папка `.venv/` с
копией интерпретатора Python и `pip` внутри. Файлы внутри `.venv/` никогда не
редактируются руками и не коммитятся в git (об этом — в шаге про `.gitignore`).

## Шаг 4. Активировать окружение

```powershell
.venv\Scripts\Activate.ps1
```

После активации слева в строке терминала появится префикс `(.venv)` — это значит,
что команды `python` и `pip` теперь указывают на интерпретатор внутри `.venv/`, а не
на системный. Активировать нужно **в каждом новом окне терминала** (это не
разовая настройка, а состояние конкретной сессии терминала).

**Частая проблема на Windows:** PowerShell по умолчанию может блокировать запуск
`.ps1`-скриптов (в том числе `Activate.ps1`) политикой безопасности, и вы увидите
ошибку про `execution of scripts is disabled on this system`. Если это произошло,
выполните один раз (разрешает запуск скриптов, написанных вами/установленных
пакетами, только для вашего пользователя):

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

и подтвердите (`Y`), затем повторите команду активации.

Чтобы деактивировать окружение (когда закончите работать): команда `deactivate`.

## Шаг 5. Выбрать интерпретатор в VS Code

Активация в терминале не связывает с `.venv` сам VS Code (подсветку ошибок,
автодополнение, кнопку "Run"). Отдельно один раз: `Ctrl+Shift+P` → набрать
*Python: Select Interpreter* → выбрать вариант, где в пути встречается `.venv`
(обычно он будет подписан как рекомендованный). Иначе редактор может подсказывать
ошибки импорта для пакетов, которые на самом деле стоят — просто не в том
интерпретаторе, который видит VS Code.

## Шаг 6. requirements.txt — список зависимостей проекта

`requirements.txt` — обычный текстовый файл, где перечислены внешние библиотеки,
нужные проекту (по одной на строку, можно с версией: `streamlit==1.38.0`). Смысл:
любой человек (или вы сами через полгода на новом окружении) может выполнить одну
команду `pip install -r requirements.txt` и получить те же зависимости, вместо
того чтобы гадать, что ставить.

Сейчас нужны только зависимости для MVP без ML и скрапинга: `streamlit`, `pandas`,
`pydantic`. Остальное (`scikit-learn`, `requests`, `beautifulsoup4`, `plotly`
и т.д.) добавим на соответствующих этапах — не тащим лишнее заранее.

Попросите Claude Code создать `requirements.txt` с этими тремя пакетами, затем
установите их (venv должен быть активен — проверьте, что в строке терминала виден
префикс `(.venv)`):

```powershell
pip install -r requirements.txt
```

`pip` — менеджер пакетов Python, `-r requirements.txt` — "поставить всё, что
перечислено в этом файле". После этого командой `pip list` можно посмотреть, что
реально установилось в текущее окружение.

## Шаг 7. Как вообще запускать Python-код

Два разных сценария, оба пригодятся дальше:

- **Обычный скрипт**: `python путь/до/файла.py` — запускает файл сверху вниз один
  раз и завершается. Подойдёт для скриптов вроде `validate_seed.py` или
  `train_classifier.py` из следующих этапов.
- **Streamlit-приложение**: не запускается через `python app.py`, а через
  `streamlit run путь/до/app.py` — эта команда поднимает локальный веб-сервер и
  сама открывает страницу в браузере (обычно `localhost:8501`). Остановить —
  `Ctrl+C` в терминале. Понадобится начиная с туториала 3.

Оба варианта требуют активного `.venv` в терминале, иначе Python либо не найдёт
установленные пакеты, либо (если `python`/`streamlit` вообще не найдены) выдаст
ошибку `command not found` / `не является внутренней или внешней командой`.

## Шаг 8. .gitignore — что не должно попадать в git

`.gitignore` — список файлов и папок, которые git должен игнорировать (не
предлагать добавить в коммит). Папку `.venv/` в git не кладут: она большая (сотни
мегабайт), полностью восстанавливается командой `pip install -r requirements.txt`
на любой машине и жёстко привязана к конкретному компьютеру — хранить её в
репозитории бессмысленно и вредно.

Попросите Claude Code создать `.gitignore` для Python-проекта (стандартный шаблон
включает `.venv/`, `__pycache__/`, `*.pyc` и т.п.).

## Шаг 9. Первый коммит

Проверить, что git видит новые файлы, и что в списке нет `.venv/` (если он есть —
значит `.gitignore` не сработал, стоит разобраться прежде чем коммитить):

```powershell
git status
```

Добавить конкретные файлы (не `git add .`, чтобы осознанно видеть, что именно
попадает в коммит):

```powershell
git add CLAUDE.md tutorials/ requirements.txt .gitignore
git commit -m "Настройка окружения проекта"
```

`git add` переносит файлы в "staging area" (то, что попадёт в следующий коммит),
`git commit -m "..."` фиксирует их в истории с сообщением. Можно попросить Claude
Code предложить формулировку commit message, но саму команду `git commit`
выполняйте осознанно, посмотрев перед этим `git status`.

## Как использовать Claude Code на этом этапе

- Попробуйте команду `/init` — она сканирует проект и предлагает `CLAUDE.md` (у нас
  он уже есть, но можно свериться, что предложит `/init`).
- Спросите в чате: *"Создай requirements.txt для Streamlit-проекта с картой и
  ML-классификацией, но пока добавь только зависимости для MVP без ML и скрапинга"* —
  это тренирует навык давать ограниченный, точный скоуп задачи.
- Спросите: *"Создай .gitignore для Python-проекта с venv"*.

## Проверка (пройдите по порядку)

1. `python --version` показывает 3.11.x.
2. После `.venv\Scripts\Activate.ps1` в терминале виден префикс `(.venv)`.
3. `pip list` показывает `streamlit`, `pandas`, `pydantic`.
4. VS Code в правом нижнем углу или через *Select Interpreter* показывает `.venv`.
5. `git status` не показывает `.venv/` как файлы для добавления.
6. `git log --oneline` показывает хотя бы один коммит.
