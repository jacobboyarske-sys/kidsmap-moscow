(~2-3 часа)

Как и на прошлом этапе: код здесь пишете вы сами вместе с Claude Code в VS Code —
ниже объяснение концепций и формулировки задач, которые стоит дать Claude Code, а
не готовые файлы для копирования.

## Шаг 1. Зачем нужна модель данных (и почему pydantic, а не просто dict)

Можно было бы хранить событие как обычный словарь: `{"title": "...", "date": "..."}`.
Проблема — ничто не мешает где-то опечататься в ключе (`"titel"`) или положить дату
строкой в неправильном формате, и это всплывёт не сразу, а где-нибудь в середине
отрисовки карты, с невнятной ошибкой.

**pydantic** — библиотека, которая позволяет описать структуру данных один раз как
класс с типами полей (`title: str`, `lat: float` и т.д.), а дальше сама проверяет
на входе: все ли поля на месте, того ли они типа, проходят ли доп. условия
(например, `age_limit` — только одно из нескольких допустимых значений). Если
что-то не так — pydantic сразу кидает понятную ошибку с указанием, какое поле и
почему не подошло, вместо того чтобы упасть значительно позже в незвязанном месте
кода. Это особенно ценно, когда данные приходят "снаружи" (вручную из JSON,
позже — из скрапера) — то есть ровно наш случай.

Библиотека уже в `requirements.txt` и должна быть установлена (`pip list` покажет
`pydantic`, если нет — `pip install -r requirements.txt` при активном `.venv`).

## Шаг 2. Спроектировать поля события

Прежде чем писать код, стоит на бумаге/в голове решить, какие поля нужны. Предлагаемый
набор (можно скорректировать под себя):

| Поле | Тип | Смысл |
|---|---|---|
| `title` | строка | Название события |
| `description` | строка | Краткое описание |
| `start_date` | дата | Когда начинается |
| `end_date` | дата (опционально) | Когда заканчивается, если многодневное |
| `address` | строка | Адрес текстом (для отображения) |
| `lat`, `lon` | число с плавающей точкой | Координаты для карты |
| `category` | строка из ограниченного набора | Тип развлечения (театр, мастер-класс, квест, спорт, кино, экскурсия, праздник) |
| `age_limit` | строка из ограниченного набора | `0+`, `6+`, `12+`, `16+` |
| `price` | строка (опционально) | Цена текстом ("бесплатно", "от 500 ₽") — на старте проще текстом, чем числом, т.к. форматы разные |
| `url` | строка | Ссылка на источник/страницу события |
| `source` | строка | Название сайта, откуда взяли (пригодится на этапе скрапинга, чтобы отличать источники) |

Поля с "ограниченным набором значений" (`category`, `age_limit`) в pydantic обычно
делают через `Literal["театр", "мастер-класс", ...]` или `Enum` — тогда опечатка
вроде `"театер"` не пройдёт валидацию, а не тихо превратится в отдельную
несуществующую категорию.

**Решение: используем `Enum`** (а не `Literal`) — даёт автодополнение в редакторе
для `category`/`age_limit` везде, где они переиспользуются дальше (фильтры,
классификатор, скраперы), и заодно практика ООП. Наследовать нужно от `(str, Enum)`,
а не просто `Enum`, иначе значения перестанут вести себя как обычные строки
(сравнение с `"театр"`, сериализация в JSON и т.п. сломаются без `.value`):

```python
from enum import Enum

class Category(str, Enum):
    THEATRE = "театр"
    WORKSHOP = "мастер-класс"
    QUEST = "квест"
    SPORT = "спорт"
    CINEMA = "кино"
    EXCURSION = "экскурсия"
    HOLIDAY = "праздник"

class AgeLimit(str, Enum):
    ZERO_PLUS = "0+"
    SIX_PLUS = "6+"
    TWELVE_PLUS = "12+"
    SIXTEEN_PLUS = "16+"
```

## Шаг 4. Попросить Claude Code написать модель `Event`

Откройте новый чат с Claude Code (или продолжите текущий) в контексте проекта и
сформулируйте задачу примерно так:

> Напиши pydantic-модель `Event` в `src/models.py` по таблице полей из
> tutorials/туториал_2.md. Для `category` и `age_limit` используй Enum-классы
> `Category` и `AgeLimit` (наследование от `(str, Enum)`, значения — как в
> tutorials/туториал_2.md), чтобы опечатки не проходили валидацию. `start_date`/
> `end_date` — реальные объекты даты, не строки.

Дальше — не принимайте код молча: спросите, почему выбран `Literal` или `Enum`,
попросите объяснить, что произойдёт, если передать `age_limit="7+"` (не из списка).
Проверить это можно прямо в терминале:

```powershell
python -c "from src.models import Event; Event(title='Тест', description='', start_date='2025-10-01', address='', lat=55.75, lon=37.62, category='театр', age_limit='7+', url='https://example.com', source='test')"
```

Должны увидеть ошибку валидации pydantic, а не тихо принятое неверное значение —
это и есть смысл всей затеи с этапом 2.

## Шаг 5. Собрать координаты для событий

Карте нужны `lat`/`lon` (широта/долгота) каждого места. Самый быстрый способ без
API-ключей: открыть **Яндекс.Карты** или **Google Maps**, найти нужный адрес,
кликнуть правой кнопкой по точке на карте — появится пункт вроде "Что здесь?" с
координатами, которые можно скопировать (обычно в порядке `широта, долгота`, то
есть `lat, lon` — именно то, что нужно). Для Москвы широта обычно около `55.7`,
долгота — около `37.6`, если числа сильно другие — вы перепутали местами lat/lon
или скопировали координаты другого города.

## Шаг 7. Сохранить в data/seed_events.json

JSON — текстовый формат для структурированных данных: список объектов в `[]`,
каждый объект в `{}`, поля через запятую. Пример одного события (посмотрите на
кавычки и запятые — в JSON, в отличие от Python, все строки строго в двойных
кавычках, а висячей запятой после последнего поля быть не должно):

```json
[
  {
    "title": "Мастер-класс по керамике",
    "description": "Дети лепят из глины под руководством мастера",
    "start_date": "2025-10-05",
    "address": "Москва, ул. Примерная, 1",
    "lat": 55.751244,
    "lon": 37.618423,
    "category": "мастер-класс",
    "age_limit": "6+",
    "price": "от 800 ₽",
    "url": "https://example.com/event",
    "source": "playforsoul.ru"
  }
]
```

Можно писать JSON руками (VS Code подсветит синтаксические ошибки — незакрытую
скобку или пропущенную запятую), а можно попросить Claude Code накидать заготовку
структуры по паре примеров, которые вы напечатаете сами.

## Шаг 8. Скрипт валидации

Смысл: прогнать весь `seed_events.json` через модель `Event` и получить список
понятных ошибок по каждой некорректной записи, а не разбираться с первой попавшейся
проблемой вручную построчно.

Попросите Claude Code:

> Напиши src/validate_seed.py — скрипт, который загружает data/seed_events.json,
> проверяет каждую запись через модель Event и печатает: сколько событий валидны,
> и для невалидных — индекс записи и текст ошибки pydantic.

Запуск:

```powershell
python -m src.validate_seed
```

(Команда `python -m src.validate_seed`, а не `python src/validate_seed.py` —
запуск как модуля внутри пакета `src`; для этого в папке `src/` должен быть пустой
файл `__init__.py`, попросите Claude Code создать его же, если её ещё нет —
обсудите, зачем он вообще нужен пакету.)
