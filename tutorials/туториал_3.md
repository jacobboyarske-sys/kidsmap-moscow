# Туториал 3. Streamlit MVP: таблица + карта

(~2-3 часа)

Цель этапа — увидеть seed-датасет живьём: таблица событий рядом с картой, с
простым фильтром по датам в сайдбаре. Пока без категорий/возраста (это туториал 4)
и без клика по маркеру, синхронизированного с таблицей (это тоже туториал 4) —
осознанно узкий скоуп, чтобы сначала увидеть карту в принципе.

Как и раньше: код пишете вы сами вместе с Claude Code — ниже объяснение концепций и
формулировки задач, а не готовые файлы для копирования.

## Шаг 1. Зачем Plotly для карты

**Plotly** — библиотека для интерактивных графиков (уже встроенный виджет в
Streamlit через `st.plotly_chart`, без сторонней прослойки вроде `streamlit-folium`
для других карт-библиотек). Кроме карты пригодится и дальше — например, для
графиков по категориям в туториале 4/5, так что не придётся держать в голове два
разных API для "обычных" графиков и для карты.

Функция `plotly.express.scatter_map` строит карту с точками по координатам
(`lat`/`lon`) на подложке OpenStreetMap — без API-ключей, аналогично folium.

Добавьте пакет в `requirements.txt` (`plotly`) и установите:

```powershell
pip install -r requirements.txt
```

## Шаг 2. Функция загрузки данных

Нужна функция, которая читает `data/seed_events.json` и возвращает список объектов
`Event` — переиспользуйте логику валидации, которая уже есть в
`src/validate_seed.py`, только вместо печати ошибок в консоль верните готовый список
(на этом этапе можно считать, что dataset уже валиден — мы это проверили в
туториале 2; функция не должна падать на валидных данных, но и не обязана
дублировать подробный вывод ошибок).

Разместите её либо в `src/app.py`, либо (чуть аккуратнее) в отдельной функции
внутри `src/models.py` или нового `src/data.py` — обсудите с Claude Code, какой
вариант нагляднее, прежде чем выбирать.

## Шаг 3. Каркас Streamlit-приложения

`st.set_page_config(layout="wide")` в начале файла — без этого колонкам будет тесно
на стандартной узкой центральной колонке Streamlit.

Основной layout — две колонки рядом:

```python
col1, col2 = st.columns(2)
```

Слева — таблица, справа — карта (или наоборот, как нагляднее покажется на экране;
это чисто вкусовое решение).

## Шаг 4. Фильтр по датам в сайдбаре

Виджет `st.date_input` с диапазоном "от – до" (`value=(дата_от, дата_до)` — если
передать кортеж/список из двух дат, Streamlit сам покажет два поля вместо одного и
вернёт кортеж выбранных границ). Разумные значения по умолчанию — например, от
сегодняшней даты до +30 дней, но не жёстко: подумайте, что удобнее для реального
использования (например, включать уже прошедшие сегодня события или нет).

Отфильтрованный список событий (по `start_date` в границах диапазона) — то, что
идёт и в таблицу, и в карту. Убедитесь, что оба виджета видят один и тот же
отфильтрованный список, а не два независимых по ошибке.

## Шаг 5. Таблица

`st.dataframe(...)` со столбцами: `title`, `start_date`, `category`, `age_limit`,
`price`. Так как `Event` — pydantic-модель, а не dict, понадобится преобразование
списка событий в `pandas.DataFrame` (например, через `[e.model_dump() for e in
events]` и выбор нужных столбцов) — самое место спросить Claude Code, почему
`model_dump()`, а не просто `e.__dict__`.

## Шаг 6. Карта

Преобразовать отфильтрованные события в `pandas.DataFrame` (аналогично шагу 5) и
построить карту через `plotly.express.scatter_map` — координаты из `lat`/`lon`,
`hover_name` для названия события, `hover_data` для адреса (с `labels={"address":
""}`, чтобы в подсказке не было технической подписи поля), `center`/`zoom` — чтобы
карта сразу открывалась на Москве, а не на весь мир. Отрендерить через
`st.plotly_chart(fig)` во второй колонке. По умолчанию всплывающая подсказка у
Plotly показывается при наведении курсора, а не при клике (в отличие от folium,
где клик открывал popup).

## Шаг 7. Запуск и проверка глазами

```powershell
streamlit run src/app.py
```

Откройте `localhost:8501` в браузере. Проверьте:
- сузьте диапазон дат так, чтобы событий осталось 2-3 — и таблица, и карта должны
  показать именно их, а не весь датасет;
- расширьте диапазон за пределы всех событий (например, только прошлый месяц) —
  должно быть пусто и понятно, что это пусто (не белый экран без объяснений).

## Как использовать Claude Code на этом этапе

- Формулируйте задачи по одной функции за раз ("напиши функцию load_events,
  которая...", затем отдельно "теперь каркас app.py с двумя колонками") — не
  просите сразу весь `app.py` целиком.
- Спросите, чем `st.plotly_chart` отличается от `st.components.v1.html` для
  показа графика — какая разница на практике (двусторонняя связь Python ↔ график
  через события выбора, которая понадобится в туториале 4 для синхронизации
  клика по карте с таблицей).
- Если карта не рендерится или падает с ошибкой импорта — почти всегда это
  забытый `pip install -r requirements.txt` после правки файла в активном venv.

## Проверка

1. `streamlit run src/app.py` открывает страницу без ошибок в терминале.
2. Таблица и карта расположены в две колонки рядом.
3. Фильтр по датам (от – до) в сайдбаре реально сужает и таблицу, и карту
   одновременно.
4. На карте видно маркеры с подсказками при наведении (название + адрес) по всем
   событиям в выбранном диапазоне.
5. Сделан коммит (`git add src/ requirements.txt tutorials/ && git commit -m "..."`).

клика по карте с таблицей), появится, когда дойдём до него.
